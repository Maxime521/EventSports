# EventSports — Project Definition

## 1. Project Identity and Organization

### Project Title

**EventSports**

### Short Description

EventSports is a web application that allows users to create, organize, and join sports events.

The goal is to make it easier for people to organize sports activities such as football matches, basketball games, running sessions, or other sports activities.

A user can create an event with information such as the sport, date, time, location, and maximum number of participants. Other users can then view the event and join it.

## 2. Problem and Target Users

### Problem Statement

Finding people to play sports with or organizing a sports activity can sometimes be difficult.

For example, someone may want to organize a football match but not have enough people to play. They may have to use group chats or social media to find participants.

Another problem is that information about the event can become confusing. People may not know the exact time, location, number of available places, or who is participating.

EventSports aims to make this process easier by putting sports events in one application.

Instead of creating a message in a group chat and waiting for people to respond, a user can create an event with all the important information and allow other users to join it.

### Target Users

The main users of EventSports will be:

- Students who want to find people to play sports with.
- People who regularly practice sports.
- People who want to organize casual sports activities.
- Sports groups that need a simple way to organize events.
- People who want to discover sports activities near them.

### User Problems

The main problems we want to solve are:

- Finding enough people for a sports activity.
- Organizing the date and time of an activity.
- Sharing the location of an event.
- Knowing how many people have joined.
- Finding available sports activities.
- Avoiding confusing conversations in group chats.

### Evidence

To validate the idea, I will ask other students and people who practice sports about how they currently organize sports activities.

I will use a short survey with questions such as:

- How do you currently organize sports activities?
- Do you usually use WhatsApp, Discord, or another application?
- Have you ever had difficulty finding enough people for a sports activity?
- Would you use an application to find or organize sports events?
- What information would you want to see before joining an event?

The answers will help me understand if the problem is relevant and which features would be the most useful.

## 3. Proposed Solution and Value Proposition

### Proposed Solution

EventSports will provide a simple platform where users can create and join sports events.

A user will be able to create an event and provide information such as:

- Sport.
- Event name.
- Date.
- Time.
- Location.
- Maximum number of participants.
- Description.

Other users will be able to browse available events and join an event if there are still places available.

### Main Features

The first version of the application will include:

- User registration.
- User login.
- User profile.
- Creating a sports event.
- Editing an event.
- Deleting an event.
- Viewing available events.
- Viewing event details.
- Joining an event.
- Leaving an event.
- Seeing the number of participants.
- Setting a maximum number of participants.
- Basic form validation.

### Example

A user wants to organize a football match.

They create an event called:

**5-a-side Football Match**

They choose:

- Sport: Football
- Date: Saturday
- Time: 18:00
- Location: Local football field
- Maximum participants: 10

Other users can see the event and join it.

When 10 people have joined, the event is full and no additional users can join.

This makes the organization of the match easier than using a group chat.

### Value Proposition

The main value of EventSports is making sports activities easier to organize and join.

The application should help users:

- Find sports activities.
- Find other people to play with.
- Organize events more easily.
- Have all event information in one place.
- Know how many people are participating.
- Avoid long and confusing group conversations.

The application will focus on being simple and easy to understand.

## 4. Scope and MVP

### MVP

The MVP is the first functional version of EventSports.

The goal is not to create a perfect or very advanced application immediately. The goal is to create the basic features needed to prove that the idea works.

### Features Included in the MVP

The MVP will include:

- User registration.
- User login.
- User profile.
- Creating a sports event.
- Editing an event.

- Viewing event details.
- Joining an event.
- Leaving an event.

The following features will not be part of the first version:

## 5. Risks, Constraints and Mitigation

### Risk 1 — The Project Becomes Too Large

**Impact:** High  
**Probability:** High

Because EventSports can have many possible features, there is a risk of trying to implement too much.

**Mitigation:**

I will focus on the MVP first.

Features such as chat, notifications, AI, and mobile applications will only be considered after the main features are completed.

### Risk 2 — Development Takes Longer Than Expected

**Impact:** High  
**Probability:** Medium

Some technical parts, especially authentication, database management, and event management, could take more time than expected.

**Mitigation:**

I will start with the most important features first and test them regularly.

If I run out of time, I will prioritize the core features and remove less important features from the MVP.

### Risk 3 — Technical Problems

**Impact:** Medium  
**Probability:** Medium

I may encounter problems with the frontend, backend, database, or deployment.

**Mitigation:**

I will test each feature separately and use GitHub to keep different versions of the project.

I will also ask my mentor for help when I am blocked by an important technical problem.

### Risk 4 — Not Enough User Feedback

**Impact:** Medium  
**Probability:** Medium

If I only develop the application based on my own ideas, some features may not actually be useful to users.

**Mitigation:**

I will ask other students and sports participants for feedback before and during development.

This feedback will help me decide which features are most important.

### Risk 5 — Responsive Design Problems

**Impact:** Medium  
**Probability:** Medium

The application may work well on a computer but have problems on smaller screens.

**Mitigation:**

I will test the application on different screen sizes during development.

The interface will be designed to work on both desktop and mobile browsers.
